# Build Version Display

## Intent

When debugging deploy issues (stale WASM, caching) there's no way to tell
which build is running. Show a subtle build timestamp in the album header so
the operator can confirm the deployed version at a glance.

## Constraints

- Must not distract from the album title/artist — tiny, muted text.
- No new crate dependencies.
- Build datetime must be baked into the WASM binary at compile time (not
  fetched at runtime), so it proves which binary is running.
- Must work in the existing `#album-header` layout without breaking
  the track-info foldout or start overlay.

**Out of scope:** git sha, semver, build-info crate integration.

## Approach

1. **Compile-time constant in `vvw-web`**: Use a `build.rs` that writes a
   `BUILD_DATETIME` constant via `env!()` or `include_str!()`. The value is
   a UTC datetime string (e.g. `"2026-03-11 05:41 UTC"`), generated by
   `chrono::Utc::now()` or plain `std::process::Command` calling `date -u`.
   Prefer the `date` command to avoid adding a build dependency.

2. **Expose to DOM from WASM**: In `ui.rs`, add a `set_build_info()` call
   alongside `populate_album_info()` that writes the constant into a
   `<span id="header-build">` element.

3. **HTML/CSS**: Add a `<span id="header-build">` inside `#album-header`,
   right-justified via `margin-left: auto`. Style: `font-size: 0.65rem`,
   `color: #444`, `white-space: nowrap`.

Layout becomes:
```
┌──────────────────────────────────────────────┐
│ Album Title                  2026-03-11 05:41│
│ Artist                                       │
└──────────────────────────────────────────────┘
```

The header already uses `display: flex` with `align-items: center`, so
`margin-left: auto` on the build span pushes it to the right edge.

## Domain Events

None. This is a display-only change — no new events produced or consumed.

The build datetime is set once at compile time and rendered once when
`show_header()` runs (on overlay click).

## Checkpoints

- [ ] `build.rs` generates a datetime constant; `cargo build -p vvw-web` embeds it
- [ ] Build timestamp visible in header bar on desktop browser
- [ ] Timestamp matches the actual `trunk build` time (not some cached value)
- [ ] Text is unobtrusive — small, muted, doesn't shift album title
- [ ] After `just deploy-album`, the timestamp on the live site matches the local build time
